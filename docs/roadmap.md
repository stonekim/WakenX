# 首版计划（待验证）

## 核心假设

用户愿意把追踪待办的工作交给 Agent，前提是它可靠、少打扰，且行动权限清晰。

## 最小闭环

1. 用户用自然语言提交待办，系统确认目标、截止日期和所属场景。
2. Agent 提出下一步；信息缺失时询问，行动前核对授权范围。
3. 按用户约定的节奏跟进状态，合并普通提醒。
4. 每日简报列出已完成、待决策和存在风险的事项。
5. 用户确认结果后关闭任务，保留可追溯记录。

## 首版边界

先支持单用户手动输入待办。家庭成员协作、邮件和日历接入、对外发送、支付和自动执行均留待后续设计；本文不构成这些功能已经实现的声明。

## 验证方式

与目标用户共同记录使用前后的每周事务追踪时间、按期完成率、无用提醒比例和人工纠错次数。只有时间负担和打扰程度得到改善，再扩大集成范围。

## 后续待决定

- 优先服务的具体人群与首个高频任务。
- 交互入口、技术栈、模型与部署方式。
- 权限、数据保留、成员隔离与失败恢复机制。
- 商业模式与开源许可。
